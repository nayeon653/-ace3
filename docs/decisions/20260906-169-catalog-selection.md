# 카탈로그 표시·선택 ID의 실험과 운영 적용 판단

## 배경

전체 카탈로그에 정답이 있어도 모델이 다른 등록 상품의 코드나 존재하지 않는 코드를
반환했다. 이름 해석과 코드 연결 중 어느 단계가 원인인지는 확정하지 않았다.
상품별 독립 행과 짧은 선택 ID가 도움이 되는지, 정확한 코드 직접 입력이나 모호·미등록
판별에는 회귀가 없는지 PR #167이 병합된 `70cd68e`를 기준으로 비교한다.

## 결정

**B와 C의 운영 적용은 보류하고 기본값 A(compact JSON·실제 코드 반환)를 유지한다.**
C는 전체 정답률과 식별자 유효성이 개선됐지만, 사전에 정한 코드 직접 입력과 미등록
판별의 무회귀 조건을 충족하지 못했다. B와 C는 명시적인 실험 옵션으로 남긴다.
같은 이슈의 구현·평가·보류 판단은 이 문서 하나에서 관리한다.

- A는 기준 프롬프트와 도구 스키마를 그대로 사용한다. B는 상품별 줄바꿈만 추가한다.
- C는 B의 전체 정보에 `row_id`를 추가한다. 모델이 `selected_row_id`를 반환하고
  Python이 같은 불변 스냅샷에서 실제 코드로 연결한다. 실제 코드도 입력에 남긴다.
- Product 이후의 조회·검색·비교 답안 계약은 실제 상품 코드를 그대로 사용한다.
- 모델이 다른 행을 선택한 의미 오류는 교정하지 않는다. 실행할 수 없는 선택만 기존
  Product 재조회 경로에 전달하며, 상품별 하드코딩과 답안 검증기를 추가하지 않는다.

## 실험

합성 22문항·35대상을 A/B/C와 원래/섞은 카탈로그 순서에서 각각 한 번 실행한다.
HCX-007·thinking none·생성 설정은 같다. 전체 100개 상품·공식명·별칭을 사용하고
각 문항의 objective는 같은 중립 문구다. 두 순서 조건을 독립 확률 반복으로 보지 않는다.

원시 모델 출력과 물리 HTTP 시도까지 보존하며, 식별자 유효성과 실제 상품 정답을 분리한다.
상품 코드 생성 오류·미등록 판별 오류도 전체 호출의 정답률에 포함한다. 완료된 쌍의
비교에서 제외된 오류를 숨기지 않는다. 채택 기준·일정·정답표·소스/프롬프트/스키마 해시는
실제 호출 전에 고정했다. 상세 재현 절차는 평가 README를 따른다.

### 132회 실제 결과

| 지표 | A: 기존 JSON | B: 상품별 행·코드 | C: 상품별 행·ID |
|---|---:|---:|---:|
| 전체 호출의 요청 정답 | 23/44 (52.3%) | 23/44 (52.3%) | 30/44 (68.2%) |
| 실행 완료 요청의 정답 | 23/35 | 23/34 | 30/40 |
| 수용된 계획의 대상 정답 | 39/70 | 39/70 | 50/70 |
| 반환된 식별자의 카탈로그 내 존재 | 50/55 | 47/57 | 57/57 |
| 원래 / 섞은 순서의 요청 정답 | 13/22 · 10/22 | 14/22 · 9/22 | 16/22 · 14/22 |
| 실행 불가 선택 오류 | 4 | 7 | 0 |
| HTTP 400 / `40009` | 5 | 3 | 4 |
| 논리 호출 / 물리 HTTP 시도 | 44 / 44 | 44 / 44 | 44 / 44 |
| 지연 중앙값 | 3.27초 | 3.26초 | 3.14초 |
| 관측 응답의 평균 입력 토큰 | 6,160 | 6,262 | 6,905 |
| 관측 입력 / 출력 토큰 합계 | 240,249 / 3,087 | 256,732 / 3,294 | 276,210 / 3,125 |

HTTP 429·timeout·재시도는 없었다. usage가 있는 응답은 A 39개, B 41개, C 40개이며
나머지의 비용을 0으로 가정하지 않는다. `40009 / Unsupported function`은 반환 계획이
없는 제공자 응답으로 별도 분류하며 원인을 모델 의미 오류나 일시적 인프라 장애로 단정하지
않는다. 합성 공통 이름 3상품 비교는 여섯 조건 모두 이 응답으로 끝나 선택 비교에 공백이 있다.

양쪽이 실행 완료된 A/B 33쌍은 요청 정답 22→22, 대상 정답 37→37로 개선이 없었다.
A/C 35쌍은 요청 23→25, 대상 39→42로 개선됐으나 다음 회귀가 있었다.

- C: `c18 original`의 정확한 코드 입력을 다른 등록 상품 ID로 연결했다.
- C: `c20 shuffled`의 미등록 대상을 `not_found` 대신 `ambiguous`로 반환했다.
- B: `c20 original`의 미등록 판별이 회귀했다.
- 모호한 단일 상품명 4조건은 모든 방식이 틀렸다. 유효한 ID가 의미 정답을 보장하지 않는다.

전체 계획이 거절됐을 때 다른 대상의 맞는 원문 선택까지 주지표에서는 0이 되는 점을
확인하고 **사후 보조 집계**도 남겼다. 원문에서 관측한 대상 정답은 A 40/70, B 40/70,
C 50/70이다. 순서별 ID를 코드로 연결할 뿐 보정하지 않으며 사전 채택 기준을 바꾸지 않는다.

정답표 SHA-256은 `4facf6ea948d16dca0bc29d2c143facd5a602ec4b4c0bb4e76d53b5093ba98ae`,
카탈로그 버전은 `6cf0aafa1dd393f8ec8d0ab432203b48d3e61186ed5e540102fe55a6335ee5de`다.
실행 전후 고정 소스 해시가 같고 독립 재채점 132개도 모두 일치했다. 개인 LangSmith 기록과
원시 요청·응답·스냅샷·MD/HTML 보고서는 `.cache/catalog-selection-169-20260906/`에 보존한다.

### 구현 검증

기본 A의 렌더링 프롬프트는 기준의 23,213 UTF-8 바이트와 같고 실제 Tool 바인딩 스키마도
동일하다. C의 표시·매핑 일치, 카탈로그 순서 변경·동시 Planner 격리, 실행 불가 ID의 원문
보존, Product 조회→검색→비교 생성 연결을 테스트했다. 실제 SDK를 사용하는 모의 HTTP
검증에서는 `429→200`을 물리 요청 2회·모델 호출 1회로 구분했다.

전체 `make check`는 1,438 passed·1 skipped이며 `make build`와 그래프 최신성 검사도
통과했다. 이 검증은 매핑·실행 계약에 관한 것이며 모델의 의미 선택이나 답변 품질의 보장은 아니다.

### 후보 C의 후속 전체 API 확인

별도 로컬 프로세스의 Product factory에만 C를 주입하고 실제 HCX·Qdrant로 3개 질문을
각 1회 실행했다. 모두 HTTP 200·정확한 5필드였지만 다음처럼 결과가 달랐다.

| 사례 | 지연 | 실제 결과 |
|---|---:|---|
| 공통 이름 3상품 비교 | 29.966초 | 정답 3개 ID→코드 연결, 15청크 검색→비교 생성→최종 6청크 |
| 변형 상품명 2상품 비교 | 34.054초 | 한 운용사 표현을 다른 운용사의 상품으로 선택, 잘못된 대응이 답변에도 반영 |
| 실제 코드 2개 직접 입력 | 1.822초 | 기존 입력 분류 모델의 `block` 오탐, Product·Catalog 미도달 |

첫 답변에도 모펀드 비율을 자펀드에 적용한 설명, 제한 조항의 예외 생략, 본문 출처 누락과
위험등급 근거의 최종 선택 누락이 남았다. Catalog 단독 실험과 질문·objective가 다른
후속 확인이므로 첫 사례의 완료를 표시 방식만의 개선으로 해석하지 않는다. 비교 답안과
입력 분류기 문제는 이번 이슈에서 변경하지 않았다.

원자료·전체 답변·흐름 보고서는 `.cache/catalog-selection-smoke-169-20260906/`에 둔다.
LangSmith 추적을 종료 후 재수집해 세 root와 모든 하위 run의 종료도 확인했다. 개인 질문
원문·추적 URL은 공개 문서에 포함하지 않는다.

## 고려한 대안과 한계

- B는 표시 변경이 작지만 코드 문자열 생성과 이름·코드 연결은 계속 모델이 담당한다.
- C는 짧은 ID를 실제 코드로 변환하는 작업이 결정론적이다. 올바른 행을 고르는 책임은
  모델에 남으며 코드 직접 입력도 잘못 해석할 수 있다. 추가 ID만큼 입력 토큰이 늘어난다.
- 정확한 코드 우선 처리, 이름별 규칙·자동 교정, 후보 검색·리랭킹은 이번 실험에 섞지 않는다.
- Catalog 단독 평가의 중립 objective와 전체 API의 Product objective는 다를 수 있다.
  이 실험만으로 전체 답안 품질이나 모든 오타 표현의 일반화를 주장하지 않는다.
