# 저장소 초기 스캐폴딩을 구현보다 먼저 준비

## 배경

세 명의 팀원이 기능 구현을 시작하기 전에 저장소 구조와 협업 규칙을 확정해야
초기 통합 비용과 충돌을 줄일 수 있다.

## 결정

팀원 초대와 애플리케이션 구현에 앞서 다음 기반을 저장소에 추가한다.

- `.gitignore`와 디렉토리 스켈레톤
- `CLAUDE.md`와 개발 컨벤션
- Git 훅과 환경 변수 예시
- GitHub 이슈·PR 템플릿

애플리케이션 로직은 비워두고 기능별 구현 PR에서 추가한다.

## 고려한 대안

- 코드 본체를 먼저 구현하는 방안은 신규 팀원의 온보딩이 다른 사람의 코드를
  이해하는 일부터 시작되고, 초반 협업 규칙을 뒤늦게 맞춰야 하므로 채택하지 않았다.

## 결과

- 팀원은 동일한 저장소 규칙과 기능별 디렉토리 경계를 기준으로 작업을 시작할 수 있다.
- 초기 구조가 실제 구현에 맞지 않으면 구현 전에 별도 결정으로 수정해야 한다.
