# 상품 비교 항목을 필요한 최소 1~3개로 제한한다

## 배경

기존 프롬프트는 일반적인 차이와 안정성 요청에 3개 항목을 지시했지만 실호출에서 요청하지
않은 비용·유동성까지 5개를 선택했다. 세 상품의 제출량이 9셀에서 15셀로 늘었으며 최종
답변은 시간 제한 안에 완료되지 못했다. 항목 수만으로 지연의 전체 원인을 설명할 수는
없지만 불필요한 검색 범위와 생성량을 먼저 줄일 필요가 있다.

## 결정

비교 항목은 한 번에 1~3개로 제한한다. 두 Tool의 입력 스키마, 카탈로그 입력 검증,
검색 config와 최종 비교 계약이 같은 상한을 사용한다. 선택 가능한 항목의 종류는 기존
5종을 유지하고 상품 대상은 최대 5개를 유지하므로 최대 제출량은 15셀이다.

- 한 항목만 요청하면 하나만 선택한다.
- 안정성만 요청하면 위험과 원금보장 2개를 선택한다.
- 일반적인 차이와 안정성을 함께 요청하면 투자전략을 포함한 3개를 선택한다.
- 비용·유동성은 명시 요청에만 선택하고 기본 비교에 추가하지 않는다.
- 요청 항목이 3개를 넘으면 사용자 목적의 핵심 항목을 우선하고, 제외한 항목은 결론과
  누락 조건에 밝힌 조건부 답변을 요구한다. Python이 입력 배열을 조용히 자르지는 않는다.

항목의 의미 선택과 미비교 범위 설명은 HCX의 책임이며 평가가 필요하다. 코드가 강제하는
것은 개수 상한과 선택된 항목의 일관성이다. 기존 출력·검색·시간 예산 결정 중 항목 상한만
이 결정으로 변경하며 나머지 값은 유지한다.

## 결과와 제한

세 상품의 차이·안정성 비교는 9셀로 이전 관찰된 15셀보다 40% 적다. 이는 셀 수 감소이며
지연이나 토큰이 같은 비율로 줄어든다는 보장은 아니다. 모·자펀드의 주체 혼동이나 인용의
의미 오류를 해결하는 변경도 아니다. 실제 항목 선택, 최종 완료와 인용 정확성은 별도로
검증한다. 세 항목을 넘는 명시 요청의 전체 비교는 한 번의 실행에서 지원하지 않는다.
