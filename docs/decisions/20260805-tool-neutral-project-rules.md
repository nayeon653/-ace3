# 공통 프로젝트 규칙을 도구 중립 파일로 분리

## 배경

프로젝트 공통 규칙이 `CLAUDE.md`에 모여 있고 `AGENTS.md`가 이를 다시 읽도록
라우팅되어 있었다. 중복을 막는 효과는 있지만 특정 에이전트의 진입점이 사람과 모든
에이전트가 따르는 중앙 정책처럼 보이고, 나중에 Claude 전용 지침을 추가하면 다른
도구에도 의도치 않게 적용될 수 있다.

## 결정

대회 제약, 개발 원칙, 컨벤션 요약, 모듈 경계와 운영 정책 링크를 도구 중립적인 루트
`PROJECT_RULES.md`에 둔다. `AGENTS.md`와 `CLAUDE.md`는 각 도구가 공통 규칙을 찾는
얇은 진입점으로만 유지하고 공통 내용을 복제하지 않는다. 문서 파싱의 상세 실행·저장·
검수 정책은 계속 `docs/operations/document-parsing.md`를 유일한 원본으로 사용한다.

## 고려한 대안

- `CLAUDE.md`를 계속 공통 원본으로 사용하는 방안은 파일의 이름과 실제 책임이
  불일치하고 도구 전용 지침과 공통 정책을 분리하기 어려워 채택하지 않았다.
- `AGENTS.md`를 공통 원본으로 사용하는 방안도 사람과 Claude에 도구 중립적인 이름이
  아니며 같은 결합 문제를 반대로 만들기 때문에 채택하지 않았다.
- 두 진입점에 공통 정책을 복제하는 방안은 변경 시 내용이 어긋날 수 있어 채택하지
  않았다.

## 결과

- 공통 정책의 소유권과 변경 범위가 특정 코딩 에이전트에서 분리된다.
- 새 도구를 추가할 때 중앙 정책을 복제하지 않고 짧은 진입점만 추가할 수 있다.
- 각 도구 전용 지침은 중앙 정책과 섞이지 않게 해당 진입점에만 둘 수 있다.
- 모든 도구가 링크된 공통 규칙을 실제로 읽어야 하므로 진입점의 안내 문장은 유지한다.
