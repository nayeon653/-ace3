# 상품 비교의 검색·답안 생성과 상품 식별 책임을 정리한다

[PR #167](https://github.com/nayeon653/-ace3/pull/167)의 2026-09-05~06 설계 변경을 하나로
관리한다. 같은 PR에서 나뉘어 작성된 ADR 5개를 통합했으며 현재 결정과 변경 이유를 함께
남긴다. 상세 실행 계약은 [비교 도구 스펙](../specs/components/product-comparison.md),
실측 결과는 [실험 기록](../experiments.md)을 따른다.

## 배경

기존 단일 상품 조회로는 명시적인 복수 상품 비교를 처리하기 어려웠다. 초기 비교 구현은
상품별 검색 뒤 Product가 대상×항목 셀을 제출했지만, 항목 확장과 누적 컨텍스트로 제출이
복잡해졌고 시간 초과도 발생했다. 셀·참조 구조가 완전해도 문장과 근거의 의미는 어긋났다.

사용자가 요청할 비교 내용을 미리 제한하기 어렵고 상품 표현에는 약칭·오타가 포함된다.
검색·생성 책임을 단순하게 모으고, 모델의 선택·답변 오류를 자동 보정으로 감추지 않는
구조를 선택한다. 이 결정의 채택은 실제 답변 품질의 채택을 뜻하지 않는다.

## 현재 결정

### 상품 식별

- Catalog Planner는 원문 질문·판단 목표와 전체 카탈로그로 조회 계획 하나를 만든다.
  약칭·오타 해석과 상품명·코드의 의미 대응은 모델이 판단한다.
- Python은 자료형·기본 계약과 카탈로그 조회의 실행 가능 여부를 확인한다. 상품명별
  고정 규칙, 후보 유일성의 의미 검사와 Planner 내부 코드 교정은 사용하지 않는다.
- 실행 불가 선택은 정제된 오류와 제출 계획을 Product에 반환한다. Product가
  `retry_hint`로 한 번 재조회할 수 있으며 질문·목표·기존 deadline을 유지한다.
  provider 호출·응답 형식 오류는 재조회하지 않고 두 번째 조회 실패도 종료한다.
- 서로 다른 확정 코드가 0~1개이면 검색·생성 없이 대상과 이유를 안내한다.
  2개 이상이면 미식별 대상도 함께 보존해 비교한다. 다른 등록 상품의 오선택은 통과할 수 있다.

### 비교 검색과 답안 생성

- Product는 `compare_products(product_codes, comparison_query)`를 호출한다. 비교 쿼리에
  사용자의 목적과 조건을 담으며 고정 항목 enum이나 항목 개수 상한을 두지 않는다.
- Python은 앞뒤 공백만 정리한 같은 쿼리로 확정 상품마다 한 번 병렬 검색한다.
  상품별 문서 범위만 바꾸며 고정 검색어 추가·자동 보완 검색은 수행하지 않는다.
- 도구 내부의 독립 HCX가 원문 질문·목표·비교 쿼리·전체 대상·상품별 검색 상태와 원문
  근거를 받아 답변과 사용한 청크 ID를 제출한다. 이전 Product 대화와 전체 카탈로그는
  넘기지 않는다. 같은 청크 ID의 원문은 한 번 전달하며 별도 요약이나 입력 토큰 상한은 없다.
- 도구가 답변까지 완료하면 Product를 종료한다. Product와 Main은 비교 답변을 재작성하지
  않는다. 식별·근거 부족 안내도 `comparison_answer`로 전달하며 셀·coverage는 만들지 않는다.

### 근거와 최종 전달

- 응답 필드·타입 파싱과 선택 ID의 실제 청크 연결은 유지한다. 없는 ID는 근거에서 제외하고
  중복은 제거하지만 그 이유로 답변을 다시 쓰거나 거절하지 않는다.
- 답변 내용·인용 의미·추천의 적절성·요청 충족 여부를 판정하는 검증기와 교정 호출은 두지 않는다.
  프롬프트는 사실의 주체·클래스·시점·예외와 직접 출처, 실제 사용 근거 선택을 안내한다.
- `comparison_answer` 본문과 조건·경고·선택 근거를 API까지 보존한다. 답변 끝에 청크별
  출처 목록을 강제로 붙이지 않는다. 외부 `/answer` 5필드와 다른 Domain의 결과·계산 처리는 유지한다.

### 실행 예산

| 경계 | 결정 |
|---|---|
| 전체 대상 | 미식별·중복 표현을 포함해 최대 5개, 확정된 서로 다른 상품별 검색 1회 |
| 카탈로그 조회 / Product ReAct | 조회 기본 1회·실행 불가 선택에 1회 추가 / 모델 최대 5회 |
| 검색 마감 | `min(진입 시각 + 30초, Domain deadline - 30초)` |
| 독립 비교 생성 | HCX-007, Thinking `none`, temperature `0.1`, 최대 출력 4096토큰 |
| 비교 Tool / 비교 생성 호출 | Tool 1회 / 생성 논리적 1회, provider timeout 30초·SDK retry 0회 |
| 공통 HTTP 429/42901 재시도 | 대기·deadline 조건을 만족할 때 최대 1회 추가 물리 호출 |
| Domain / API deadline | 기존 75초 / 180초, 부모 deadline·취소와 공통 동시성 제한 우선 |

Product ReAct 출력 4096토큰과 Catalog Planner 출력 1024토큰을 유지한다. 생성에 남기는
30초는 완료 보장이 아니며, 새 역할이나 재시도 때문에 부모 마감을 연장하지 않는다.

## 변경 이력

같은 PR의 검토 과정이며 아래의 초기·중간 설계를 현재 계약으로 해석하지 않는다.

| 순서·시기 | 당시 접근 | 변경 이유와 현재 반영 |
|---|---|---|
| 1 · 09-05 | Python 검색 후 Product가 최대 25개 셀 제출, 출력·검색 예산 분리 | 구조화 제출량과 시간 부족에 대응했다. 현재도 생성 여유와 출력 예산은 유지하고 셀 제출·보완 검색은 제거했다. |
| 2 · 09-06 | 고정 비교 항목을 1~3개로 축소 | 불필요한 범위 확장을 줄이려 했지만 사용자 요청 범위를 제한했고 인용 의미 오류도 해결하지 못했다. 최종적으로 개수 제한과 enum을 없앴다. |
| 3 · 09-06 | Product 작성 직전 입력만 새로 구성하는 초안 | 답변 소유권을 도구로 옮기면서 별도 Product middleware·snapshot 검사·재제출 순환은 채택하지 않았다. |
| 4 · 09-06 | 도구가 독립 입력에서 답안 생성까지 완료 | 누적 대화와 작성 입력을 분리했다. 셀 구조 통과가 의미 정확성을 보장하지 않아 셀 검증·답안 교정을 제거했다. |
| 5 · 09-06 | 출처 자동 첨부 제거, 범용 인용 프롬프트 정리 | 선택 청크 전체가 본문에 필요한 근거는 아니었다. 직접 출처·실제 사용 ID를 모델이 선택하도록 안내하되 개선은 입증하지 못했다. |
| 6 · 09-06 | 상품 이름 가드·Planner 내부 코드 교정 제거 | 오타·약칭을 고정 규칙으로 제한하지 않고 실행 불가 선택만 Product에 드러내 한 번 재조회하도록 했다. |
| 7 · 09-06 | 자유 비교 쿼리를 검색·생성에 함께 전달 | 사용자 요청을 고정 항목에 맞추는 단계를 없앴다. 남아 있던 미확인 셀 안내와 미사용 보완 검색도 정리했다. |

## 결과와 후속 과제

- 비교 검색·독립 생성·최종 전달의 책임은 연결됐지만 상품 선택과 답변 품질은 별도 평가가
  필요하다. 잘못된 등록 상품 선택, 모·자펀드와 예외 혼동, 인용·조건 누락이 관찰됐다.
- 자유 쿼리 실호출에서 동일 쿼리의 검색·작성 입력과 최종 본문 보존을 확인했다. 다른 요청은
  HCX 429/42901로 비교 단계에 도달하지 못했다. 완료율·지연·품질 개선을 단정하지 않는다.
- [후속 실험 #169](https://github.com/nayeon653/-ace3/issues/169)에서 카탈로그 표시와 짧은
  선택 ID의 효과를 별도 PR로 비교한다. 아직 채택한 설계가 아니며 실제 상품 정답률과
  식별자 유효성을 나누어 평가한다. 후보 검색·자동 교정·답변 검증기는 이 실험 범위에 넣지 않는다.
- 과거 항목·셀 방식의 실험을 최종 자유 쿼리의 검색 적합성이나 답변 품질의 근거로 사용하지 않는다.
- 상세 관찰·실행 설정은 실험 기록에 유지한다. 개인 질문·실행 원문·LangSmith 링크는
  공개 문서에 포함하지 않는다.
