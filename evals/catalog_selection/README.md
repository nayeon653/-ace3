# 카탈로그 표시·선택 계약 실험

[이슈 #169](https://github.com/nayeon653/-ace3/issues/169)의 공개 합성 질문과
실행기다. 제품 카탈로그 전체를 읽는 HCX-007의 상품 선택만 비교한다.
검색과 비교 답안의 품질은 별도 전체 흐름 smoke로 확인한다.

## 호출 전에 고정한 조건

기준 커밋은 PR #167이 병합된 `70cd68e`다. A는 기존 프롬프트·도구 계약을
그대로 렌더링한다. B는 상품 간 줄바꿈만 추가한다. C는 B에 `row_id`를
추가하고, 모델이 `selected_row_id`를 반환하면 Python이 같은 스냅샷의 실제
상품 코드로 연결한다. C에도 실제 코드를 남겨 코드 직접 입력을 지원한다.
C의 추가 ID 필드와 선택 안내·도구 필드 차이는 실험 처치에 포함된다.

- 전체 100개 상품의 코드·공식명·운용사·별칭을 세 조건에 동일하게 제공한다.
- `cases.json`의 22문항·35대상을 수정하지 않고 사용한다. 모든 objective는
  같은 중립 문구이며 정답 코드·공식명을 덧붙이지 않는다.
- 원래 순서와 seed 169로 한 번 섞은 순서를 각각 실행한다. 각 문항·순서·방식당
  1회, 총 **132개 논리 호출**이다. 두 순서 조건이며 독립 확률 반복 2회가 아니다.
- 원래 순서 다음 섞은 순서를 실행하고, 각 문항의 A/B/C 시작 위치를 순환시킨다.
  실제 schedule·카탈로그·프롬프트·도구 schema·소스 해시는 첫 호출 전에 저장한다.
- 모델 설정은 `DEFAULT_DOMAIN_AGENT_HCX_CONFIG` 그대로 사용한다. HCX-007,
  thinking none, temperature 0.1, 출력 상한 1024, SDK timeout 30초·재시도 2회다.
- 외부 호출은 순차 실행한다. 호출 시작 간격은 최소 10초, HTTP 429가 한 번이라도
  발생한 논리 호출 뒤에는 최소 30초를 쉰다. 논리 호출 deadline은 75초다.
- 기존 공통 concurrency/retry middleware를 그대로 쓴다. SDK 내부 재시도와
  middleware의 제한된 429 재호출을 합쳐 논리 호출당 최대 6개 물리 HTTP 요청이
  가능하다. 별도의 의미 오류 재질문이나 성공할 때까지 재평가는 하지 않는다.

## 정답과 집계

입력에 나열된 순서대로 대상의 상태와 실제 상품 코드를 채점한다. 전체 정답은
route·대상 개수·모든 대상의 정답이 일치해야 한다. `ambiguous`와 `not_found`는
코드 없이 해당 상태를 반환해야 한다. 같은 공식명으로 여러 코드가 등록된 사례는
모호함이 정답이다. 클래스 표현은 현재 문서 카탈로그의 펀드 단위로 식별하며,
카탈로그에 없는 클래스별 코드를 만들지 않는다. 문항별 이유는 cases에 둔다.

상품 의미 정답률과 반환 식별자의 카탈로그 내 존재 비율은 별도로 집계한다.
유효한 다른 상품을 선택하면 식별자는 유효하지만 정답은 아니다. 모든 호출을
분모에 포함한 정답률과 실행 완료 호출의 정답률을 함께 보고한다. 정상·약칭·오타·
띄어쓰기·이름 생략·유사 상품·모호함·미등록·코드 입력·복수 요청 및 순서별 결과를
분리한다. 같은 문항·순서의 세 결과를 짝지어 개선과 회귀도 확인한다.

물리 HTTP 요청·응답, 최초와 최종 모델 출력, Python이 수용한 계획, 오류 체인,
입출력 토큰, 지연을 원자료로 남긴다. HTTP/timeout 실패와 출력 형식·미등록 식별자
오류를 구분한다. SDK에서 복구된 HTTP 오류도 지우지 않는다. 인증 헤더는 기록하지
않는다. LangSmith는 개인 로컬 설정으로 추적하며 추적 실패가 선택 결과를 바꾸지 않는다.

## 사전 채택 기준

완료된 동일 문항·순서 쌍에서 A 대비 전체 요청 및 대상 정답이 개선되고,
원래/섞은 순서 각각에서 대상 정답이 악화되지 않으며, 코드 직접 입력과
모호·미등록 판별에 새 회귀가 없는 방식을 채택 후보로 삼는다. B와 C가 같으면
더 단순한 B를 우선한다. 차이가 작거나 순서에 따라 상반되거나 인프라 실패로
판단이 어려우면 보류한다. 이 표본만으로 통계적 일반화나 오타 전체 해결을 주장하지
않는다. 결과를 본 뒤 정답표·기준을 바꾸거나 선택 오류를 자동 교정하지 않는다.

## 실행

저장소 루트에서 개인 `.env`를 준비하고 실행한다. 호출과 추적 정책은
[운영 문서](../../docs/operations/langsmith-tracing.md)를 따른다.

```bash
uv run python -m evals.catalog_selection.run --output .cache/catalog-selection-169
uv run python -m evals.catalog_selection.report --input .cache/catalog-selection-169
```

실행기는 출력 디렉토리가 이미 있으면 중단한다. 원문·응답·추적 정보가 있는
`.cache/`는 커밋하지 않는다. 공개 결정 기록에는 합성 문항별 선택과 집계·한계만
요약한다. 호출 실패를 제거한 재실행으로 기존 결과를 덮어쓰지 않는다.
