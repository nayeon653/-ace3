# 코덱스로 답변 평가하기

코덱스에 정답셋과 Agent의 실제 응답을 제공하고, 아래 기준으로 문항별 평가를 요청한다.

## 평가 입력

| 정답셋 | 문항 수 |
| --- | --- |
| [한투 정답셋](gold/hantoo_selected_30.table.md) | 30 |
| [미래에셋 정답셋](gold/miraeasset_actual_86.table.md) | 86 |

정답셋에는 문항 ID·질문·최종 정답만 둔다. 정답을 수정할 때는 해당 파일을 직접 수정한다.
검토 과정과 수정 이유는 PR에 기록한다.

실제 응답은 문항 ID·질문·답변·검색 근거(`retrieved_context`)가 포함된 결과 파일을 사용한다.
평가 전에 ID와 질문을 대조하고, 누락·중복·실행 실패는 별도로 기록한다.

## 공통 채점 기준

- 정답과 표현·문장 순서가 달라도 핵심 의미와 조건이 같으면 인정한다.
- 핵심 결론, 수치, 적용 대상, 예외 조건이 맞는지 확인한다.
- 일부 핵심 내용이 빠졌거나 조건 설명이 불충분한 경우를 구분한다.
- 근거 없는 절차·상품 추천·단정이나 질문에 없는 전제를 추가했는지 확인한다.
- 자료로 확인할 수 없다는 정답에서는 불확실성과 확인이 필요한 조건을 적절히 설명했는지 본다.
- 검색 근거가 실제 답변을 뒷받침하는지 확인한다. 정답 문구가 같아도 제시한 근거가 무관하면 평가 이유에 남긴다.
- 정답과 실제 응답이 충돌하면 제공 문서를 우선 확인한다. 정답 자체의 오류나 최신성 문제가 의심되고 확인할 자료가 부족하면 보류한다.

## 평가 결과

| 판정 | 의미 |
| --- | --- |
| 정답 | 핵심 결론과 필요한 조건이 맞고, 확인된 오류가 없음 |
| 부분 정답 | 핵심 방향은 맞지만 중요한 내용이 누락되거나 설명이 불충분함 |
| 오답 | 핵심 결론·수치·대상이 틀리거나 근거 없는 단정으로 잘못 안내함 |
| 보류 | 정답 자체의 오류·근거 충돌 등을 해결할 자료가 부족해 판정하기 어려움 |

| ID | 판정 | 이유 | 수정할 점 |
| --- | --- | --- | --- |

평가 기록에는 사용한 정답셋의 커밋과 실제 응답 파일 경로를 함께 적는다.
전체 요약에는 판정별 문항 수와 반복되는 오류를 적고, 누락·중복·실행 실패는 구분한다.
저장할 때는 `evals/results/`에 `<정답셋 이름>.codex-review.md`로 둔다.
